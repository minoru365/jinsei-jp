# Feature Specification: ホーム画面 — 今年のイベント一覧

**Feature Branch**: `001-home-screen-yearly-events`
**Created**: 2026-05-09
**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 今年のイベントをホームで確認する (Priority: P1)

ユーザーがアプリを起動すると、登録メンバー全員の「今年の誕生日」と「今年中に到来するライフイベント」が日付順に一覧表示される。誰のイベントかが一目でわかり、タップすることでそのメンバーの詳細タイムラインに移動できる。

**Why this priority**: アプリの起動時エクスペリエンスそのものであり、最も利用頻度が高いビュー。

**Independent Test**: アプリを起動しただけで、登録済みメンバーのイベント一覧が表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数のメンバーが登録されている、**When** アプリを起動する、**Then** 今年中のイベント（誕生日・ライフイベント）が全メンバー分、日付昇順で一覧表示される
2. **Given** イベント一覧が表示されている、**When** 特定のイベント行をタップする、**Then** そのメンバーのタイムライン詳細画面に遷移する
3. **Given** まだ来ていない誕生日と過ぎた誕生日が混在する、**When** 一覧を見る、**Then** 過ぎた誕生日も含めて日付昇順で表示される（当日が最も上になるよう優先しても可）
4. **Given** あるメンバーに今年のライフイベントが存在する、**When** 一覧を見る、**Then** 誕生日と区別できるラベル（例：「成人」「小学校入学」など）と共にメンバー名が表示される

---

### User Story 2 — 登録メンバーがいないときの案内 (Priority: P2)

メンバーが1人も登録されていない状態でアプリを起動したとき、空状態のメッセージが表示され、メンバー追加の操作に誘導される。

**Why this priority**: 初回起動体験に直結し、ユーザーが次の行動に迷わないために必要。

**Independent Test**: メンバーゼロの状態でアプリを起動して空状態メッセージが表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** メンバーが0人、**When** アプリを起動する、**Then** 「メンバーを追加してください」趣旨のメッセージと追加ボタンが表示される
2. **Given** 空状態画面が表示されている、**When** 追加ボタンをタップする、**Then** メンバー追加フォームに遷移する

---

### User Story 3 — 表示年を前後に切り替える (Priority: P2)

ホーム画面で表示する年を前後に送ることができる。初期表示は今年だが、来年・再来年や過去年のイベントも確認できる。

**Why this priority**: 誕生日プランや先の学校入学などを事前に把握したいニーズがある。

**Independent Test**: ホーム画面で年を切り替えて、対象年のイベントが正しく表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ホーム画面が今年を表示している、**When** 「次の年」ボタンをタップする、**Then** 来年のイベント一覧に切り替わり、表示中の年が明示される
2. **Given** ホーム画面が今年を表示している、**When** 「前の年」ボタンをタップする、**Then** 昨年のイベント一覧に切り替わり、表示中の年が明示される
3. **Given** 任意の年を表示している、**When** アプリを再起動する、**Then** 初期表示は今年に戻る

---

### User Story 4 — タブバーで個人タイムラインに切り替える (Priority: P3)

ホーム画面（一覧ビュー）を見ているとき、画面上部のタブバーからメンバー名をタップすると、従来の個人タイムライン詳細ビューに切り替わる。

**Why this priority**: 既存機能との共存・整合性のため。

**Independent Test**: ホーム画面を表示した状態でタブをタップし、個人タイムラインに切り替わることを確認できる。

**Acceptance Scenarios**:

1. **Given** ホーム画面が表示されている、**When** タブバーのメンバー名をタップする、**Then** そのメンバーの個人タイムライン詳細に切り替わる
2. **Given** 個人タイムラインを表示している、**When** 「ホーム」相当のタブまたはボタンをタップする、**Then** 全体一覧のホーム画面に戻る

---

---

### Edge Cases

- メンバーは登録済みだが今年のイベントが1件もない場合、「今年のイベントはありません」などの空状態メッセージを表示する
- 端末の日付が年をまたいだとき（12月31日 → 1月1日）、次回起動時に今年のイベントが更新されていること
- 1人のメンバーが同じ日に誕生日とライフイベント両方を持つ場合、両方を別行として表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ホーム画面は登録メンバー全員の「表示年の1月1日〜12月31日」に該当する誕生日とライフイベントを取得して表示する
- **FR-001b**: 初期表示年はデバイスのローカル日時から取得した今年とする
- **FR-001c**: ホーム画面に「前の年」「次の年」の操作（ボタン等）と現在表示している年を表示する
- **FR-001d**: 年切り替えはアプリ内セッション中のみ保持し、再起動時は今年に戻る
- **FR-002**: イベント一覧は日付昇順で表示する（同日の場合はメンバー名の登録順）
- **FR-003**: 各イベント行にはメンバー名・イベント種別（誕生日 or イベント名）・日付を表示する
- **FR-004**: イベント行をタップしたら、そのメンバーの個人タイムライン詳細に遷移する
- **FR-005**: 登録メンバーが0人の場合は空状態メッセージを表示し、メンバー追加操作へ誘導する
- **FR-006**: 登録メンバーはいるが今年のイベントが0件の場合は「今年のイベントはありません」趣旨のメッセージを表示する
- **FR-007**: タブバーからメンバー名をタップすると個人タイムライン詳細ビューに切り替わる
- **FR-008**: アプリ起動時のデフォルトビューはホーム画面（全員一覧）とする
- **FR-009**: データはデバイスローカルのみから取得する（外部通信なし）
- **FR-010**: 既存の `buildAllEvents` / `calendar` ユーティリティを活用してイベント計算を行う

### Key Entities

- **Person**: 登録メンバー。名前・性別・生年月日などを持つ
- **YearlyEventItem**: 表示用の集計エンティティ。メンバー参照・イベント名・日付・種別（birthday / lifeEvent）を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: アプリ起動からホーム画面の表示完了まで、体感的に待ちを感じない（スクロール可能な一覧が即座に表示される）
- **SC-002**: 登録メンバーが10人・各自5件のイベントを持つケースでも一覧が正しく50件以内で表示される
- **SC-003**: イベント行タップから個人タイムライン表示まで、追加の読み込み待ちなく遷移できる
- **SC-004**: 空状態（メンバーゼロ）の場合にユーザーが次の操作（メンバー追加）に迷わない（メッセージ＋誘導ボタンが1タップで到達できる）

## Assumptions

- 初期表示年はデバイスのローカル日時から判定する（タイムゾーン変換は不要）
- 年切り替えに上限・下限は設けない（メンバーの生年が遠い過去でも操作可能）
- ライフイベントの計算には既存の `buildAllEvents` 関数を流用し、その年の結果をフィルタリングする
- 追加ライブラリはインストールしない（Expo / React Native 標準 + 既存 deps のみ）
- データはすべて AsyncStorage に保存されたローカルデータのみを使用する
- UI は日本語表記で統一する
- タブバーの「ホーム」ボタン or 表示切り替えの具体的な UI パターンは設計フェーズで決定する
- 既存のタブバー（メンバー名タブ）は変更せず、ホームビューとの切り替え方は計画フェーズで設計する
